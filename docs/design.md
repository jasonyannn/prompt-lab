# Design

How Prompt Lab looks, behaves and is put together — and the reasoning behind the
decisions that were not obvious.

---

## Visual language

Dark, dense, technical. The product sits between a developer tool and a
consumer library, and the interface leans developer: monospace for prompt
bodies, tight vertical rhythm, restrained colour.

### Tokens

All defined on `:root` in `src/styles.css`.

| Token | Value | Used for |
|---|---|---|
| `--bg` | `#0b0d12` | Page ground |
| `--panel` | `#12151d` | Cards, panels |
| `--panel-2` | `#171b25` | Raised surfaces, hover |
| `--line` | `#242a38` | Borders |
| `--line-soft` | `#1c212c` | Internal dividers |
| `--text` | `#e8ecf4` | Primary |
| `--text-dim` | `#97a1b5` | Secondary, prompt bodies |
| `--text-faint` | `#626d81` | Labels, metadata |
| `--accent` | `#7c8cff` | Interactive, selection, brand |
| `--good` | `#46d39a` | Saved states, quick tier |
| `--warn` | `#f0b849` | Master tier |
| `--bad` | `#ff6b6b` | Errors, destructive |

Radii: `12px` cards, `8px` controls, `999px` chips. Type: system sans for UI,
`ui-monospace` for prompt content. Base size 14px, metadata 10–11.5px.

The brand mark is a rounded square with an accent→green gradient and a prompt
caret. It appears in the topbar and as the favicon (`public/favicon.svg`), and
the two are deliberately identical.

### Colour carries meaning

Accent means *interactive or selected*. Green means *already saved* — used
consistently for "In library", saved variant chips and the quick tier. Amber is
reserved for the master tier. Red only appears for errors and destructive
confirmations. Nothing is coloured decoratively.

## Structure

Three top-level views, in the order a new user should meet them:

**Discover** (default) — a category rail, a goal search, journey cards, then a
prompt grid. This is the front door because the product's thesis is that people
do not know what to ask.

**Library** — three columns: list with filters, prompt detail with variables and
evaluation, and a right rail carrying the agent chat and the activity feed.

**Prompt Studio** — a guided brief that produces a connected prompt pack, plus
predicted follow-ups.

### Layout patterns

- `.discover-layout` — 260px rail + fluid main.
- `.columns` — 340px / fluid / 320px, the Library workspace.
- `.studio-layout` — agent rail + fluid main.

All three collapse to a single column at 820px. The catalog grid steps 3 → 2 → 1
across 1050px and 820px.

## Interaction principles

### 1. Instant by default, model when it helps

The Studio pack and the predictive prompts are generated by **deterministic
engines** — recipes in `promptGenerator.ts`, a 35-angle bank in
`predictivePrompts.ts`. They are instant, free, work offline and cannot fail.

The model is offered alongside as an upgrade, never as a replacement. A pack of
four prompts from gpt-5.2 takes around 28 seconds and roughly 1,400 output
tokens; that is fine as a choice, fatal as a default. If a model call fails, the
UI falls back to the deterministic pack and says so rather than showing an empty
state.

This is why the engine toggle exists rather than a spinner.

### 2. Nothing saves without consent

The agent proposes; the person disposes. Prompts the agent wants to create stage
into a review tray with per-row **Save**, checkboxes with **Select all**, a
category picker, and **Save all**. The library is the user's, and an agent
writing to it unasked is a bug.

### 3. Show what the system is thinking

The predictive panel lists the signals it read from your brief ("Software build",
"Money & pricing") before showing predictions. The confidence percentage on each
prediction is honest about being a heuristic. The activity feed logs every tool
call, from any surface. Users trust systems whose reasoning they can see.

### 4. Recovery over prevention

When the agent lists prompts as prose instead of proposing them, a row appears
offering to convert them. Rather than only tightening the system prompt and
hoping, there is a visible way out of the failure state.

The detection is deliberately narrow — it counts list items against question
marks, because clarifying questions are numbered too and an over-eager offer is
worse than none.

### 5. Progressive disclosure

Variants, journey steps, prompt bodies and chat history are all collapsed by
default and expand in place. The catalog card says "18 role versions" rather than
showing eighteen chips.

## Component inventory

| Component | Job |
|---|---|
| `Discover` | Catalog browse, goal search, journeys, variant picker |
| `PromptList` | Filters, category chips with inline creation, sort |
| `PromptDetail` | Prompt body, `{{variables}}` fill, rating, evaluation |
| `PromptStudio` | Guided brief, template picker, pack generation |
| `PredictivePrompts` | Signals, batch size, predictions, save-to-category |
| `AgentChat` | Conversations, provider toggle, proposal tray, prompt picker |
| `AgentManager` | Agent profile CRUD |
| `KnowledgeLibrary` | Per-agent saved files |
| `AttachmentPicker` | Local file intake with extraction |
| `RightRail` | Agent / Activity tabs |

### Recurring patterns

- **Pill toggle** (`.engine-toggle`, `.predict-size`, `.tier-filter`) — two or
  three mutually exclusive options, accent fill on the active one.
- **Chip** (`.chip`, `.variant-chip`) — filters and selections. Dashed border
  means "add new".
- **Tray** (`.proposal-tray`) — a pending decision above the composer.
- **Save-into row** (`.save-into`) — a category select next to a save action,
  used identically in Discover, the predictive panel and the chat tray.

## Writing

Interface copy is plain, specific and unhyped. Labels say what happens
("Save this version", "Predict 4 more"), not what the feature is called.

Prompt content follows one house structure everywhere — catalog, Studio,
predictions and model generation all emit the same shape:

```
Act as <role>.

Objective          — one sentence
Context I am giving you   — {{placeholders}} the user fills
Before you begin   — ask ≤3 questions, never invent facts
Process            — 3–5 concrete steps
Return exactly     — 4–6 named output sections
```

Master-tier prompts substitute **Stages** for Process and instruct the model to
finish each stage before moving on. The consistency is the point: a person who
learns to read one Prompt Lab prompt can read all of them, and the
`{{placeholders}}` mean every saved prompt works with the variables panel with no
extra step.

## Accessibility

Present today: semantic buttons throughout, `aria-pressed` on toggles,
`aria-expanded` on disclosures, `aria-live` on generated regions, labelled form
controls, a `.visually-hidden` utility, and visible focus via accent shadows.

Known gaps, worth an audit:

- No focus trapping or restoration when trays and pickers open and close.
- Contrast of `--text-faint` (`#626d81`) on `--panel` is below WCAG AA for small
  text. It is used for metadata, but it is used a lot.
- The category chip row reaches ~21 items with no keyboard grouping.
- Long model calls (30s+) announce only via a status paragraph.
- No reduced-motion handling, though animation is minimal.

---

## Responsive

Desktop-first, honestly. The three-column Library is the primary experience.
Breakpoints at 1100px (columns collapse), 1050px (grids step down), 820px (single
column, rails become horizontal) and 560px (chrome sheds: export/import and
status hide, controls go full width).

The weakest area is the Library on a phone: three columns become three stacked
sections, which is functional but long. A tab switcher would serve better.

---

## Open design problems

1. **Category chips are outgrowing their row.** 17 defaults plus custom plus
   prompt-derived categories is around four rows before content starts. Options:
   show only non-empty categories, or a "more" disclosure.
2. **Two libraries, one mental model.** Nothing in the UI explains that the
   browser library and the remote MCP library are different collections.
3. **Journeys end at "saved".** No progress, no resume, no sense of completion.
4. **`Test · N` implies execution.** It is a static heuristic score. Either
   rename it or make it actually run the prompt.
5. **No empty-state onboarding.** A first-time visitor gets the full catalog with
   no orientation.
